# Unslop evaluation rubric

1. Pattern removal: authored prose removes every applicable owned pattern.
2. Meaning: edits preserve claims, normative force, permission, uncertainty,
   and technically meaningful time relations.
3. Tone: prose stays direct and suitable for its original audience.
4. Exact text: code, identifiers, commands, parser tokens, source returns, and
   vendor stdout remain byte-identical where the prompt marks them as source.
5. Source grounding: every substantive Research assembly claim follows from a
   completed Research return, never task-only context.
6. Source ownership: completed Research returns remain byte-identical wherever
   the output presents them as source spans.
7. Helper contract: each non-vendor helper Reads the four supplied prose files,
   preserves evidence tokens and line caps, and applies the ordered audit.
8. Parent fallback: an unreadable prose file causes the named parent to reject
   the helper return and gather independent evidence inline.
9. Assessment guard: the technical writer and fresh DESIGN reviewer do not
   report normative force, permission, uncertainty, or meaningful time
   relations as readability defects.
10. Fresh review: the DESIGN reviewer uses only the supplied artifact and ends
    with one valid terminal verdict.
